# Windows-приложение «Элехант» (черновик)

## 1. Цель

Один **.exe**, который любой человек запускает на домашнем Windows-компьютере:

- находит счётчики Элехант по BLE;
- собирает показания **постоянно**, пока приложение открыто;
- показывает график расхода/температуры;
- считает расхождения с показаниями на табло;
- по желанию считает **деньги** (тариф можно не вводить).

Без установки Python, без облака, без аккаунта. BLE-адаптер — обычный
USB-Bluetooth (Windows 10/11).

## 2. Экран

### Главная

Карточки приборов:

```
Ванна холодная (СВД-15)      247.3040 м³   +0.0000 за час
  температура 23.2 °C   батарея 67/127   вода: нет   пакет 2 мин назад

Ванна горячая (СВТ-15, канал 03/04)
  ниже +40 °C: 0.5324 м³   выше +40 °C: 1.2464 м³
  температура 31.7 °C   вода: идёт (0.8 л/мин)
```

### Графики (вкладки)

1. **Расход** — м³/час и м³/сутки; отдельно холодная/горячая.
2. **Температура** — линии по приборам; маркеры «температура без воды».
3. **Расхождение** — наше значение минус показание с табло (пользователь
   вводит эталон); в м³ и %.
4. **Деньги** — только если тариф заполнен; иначе вкладка скрыта.

### Настройки

- тариф холодной/горячей воды, ₽/м³ — **необязательно**;
- эталонное показание с табло (для сверки);
- папка данных;
- выбор BLE-адаптера (если их несколько);
- «хранить сырые пакеты» (для отладки).

## 3. Логика «вода идёт / не идёт»

Ключевое: **температура сама по себе не означает расход**.

| Событие | Что делаем |
|---|---|
| `ΔV > 0` (объём вырос) | вода идёт; ΔV — расход; учитываем в графике/деньгах |
| `ΔV = 0`, температура изменилась | **вода не идёт**; обновляем только температуру, расход = 0 |
| `ΔV = 0`, всё same | пакет «жив», расход 0 |
| `ΔV < 0` (кроме rollover 99999.9999) | замена/сброс прибора; помечаем, не считаем отрицательный расход |
| счётчик пакетов прыгнул | потеря пакетов; расход **не выдумываем**, показываем «нет данных» |
| нет пакетов > N минут | «прибор молчит»; расход 0, но предупреждение |

### Деньги

```
стоимость = Σ(ΔV по прибору × тариф прибора)
```

- тариф пустой → деньги не считаются, показываем только м³;
- тариф можно задать отдельно для холодной/горячей;
- температура/пакеты без ΔV **не добавляют деньги**;
- округление — как у табло (0.001 м³), но храним 0.0001 м³ (0.1 л).

### Расхождение с табло

Пользователь вводит текущее показание табло. Приложение:

```
Δ = decoded_volume − reference_display
```

- Δ в пределах ±0.001 м³ — норма (округление табло);
- больше — показать предупреждение, сохранить историю;
- не «подкручивать» декодер под табло.

## 4. Данные

Локально, без SQLite (правило проекта — PostgreSQL только в основном контуре;
у публичного приложения — файлы):

```
data/
  readings-YYYY-MM-DD.jsonl   каждый пакет: время, MAC, тип, канал,
                               volume_m3, temp_c, battery_raw, flags,
                               packet_counter, rssi
  references.json             эталоны с табло
  settings.json               тарифы (если заданы), путь, выбранный адаптер
```

Экспорт: CSV (Excel) и PNG-график.

## 5. Архитектура

```
Tkinter UI (main thread)
   ▲ queue
BLE-сканер (bleak, background thread/asyncio loop)
   │
JSONL writer + агрегатор (почасовые/суточные)
   │
графики (matplotlib, TkAgg)
```

Почему не Electron/Web: один exe, без Node, меньше зависимостей.

## 6. Сборка exe

```powershell
py -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\pip install pyinstaller
.venv\Scripts\pyinstaller --noconfirm --onefile --windowed ^
  --name Elehant ^
  --add-data "assets;assets" ^
  elehant_app.py
```

Результат: `dist\Elehant.exe` (~60–90 МБ из-за matplotlib; можно `--onedir`).

Требования: Windows 10/11 x64, Bluetooth 4.0+, .NET не нужен.

## 7. Что важно не делать

- не подключаться GATT (его нет);
- не выдавать сырой байт батареи за проценты;
- не считать температуру расходом;
- не «дорисовывать» данные при пропаже пакетов;
- не отправлять данные в облако без согласия;
- не заменять официальный учёт — приложение для контроля.

## 8. Этапы

1. Прототип: BLE → JSONL → таблица (без графика).
2. График расхода/температуры.
3. Сверка с табло и деньги (необязательный тариф).
4. Логика «вода/без воды», пропуски, rollover.
5. Сборка exe, тест на «чистой» Windows.
6. Подпись/антивирус (по желанию), portable-режим.

## 9. Что нужно от владельца

- подтвердить, что тариф **необязателен** и по умолчанию пустой;
- решить, показывать ли два канала СВТ отдельными карточками (я — за);
- нужен ли экспорт в Excel или CSV достаточно;
- нужен ли русский/английский интерфейс.
