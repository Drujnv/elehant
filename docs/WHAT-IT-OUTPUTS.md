# Что Элехант отдаёт — полная карта

## 1. По BLE-рекламе (сейчас читаем)

| Данные | Где | Точность/формат | Статус |
|---|---|---|---|
| объём воды/газа | байты 9–12 | u32, 0.1 л; м³ = /10000 | подтверждено |
| температура воды | байты 14–15 | u16, 0.01 °C | подтверждено; есть у холодных |
| тип/модель | байты 2–5 | `96 01 02` вода / `96 01 01` газ | подтверждено |
| канал/тариф | байт 5 + адрес | 01, 03, 04… | подтверждено |
| серийный номер | байты 6–8 | u24 little | подтверждено, совпадает с адресом |
| счётчик пакетов | байт 1 | +1 за передачу | подтверждено |
| RSSI | BLE-стек | дБм | доступно сканеру |
| интервал | время между пакетами | секунды | вычисляется |
| заряд батареи (сырой) | байт 13 | 0–127? | **гипотеза** |
| статус/флаги | байт 16 | 0x21 вода, 0x0F газ? | **не выяснено** |
| версия/модель в B1 | B1:* | 17 байт | **не выяснено**, сохраняем |

## 2. Что знает облако (но не отдаёт в приложение явно)

Флаги профиля `showBattery`, `showTemperature`, `showFirmware`,
`showCheckUpDate`, `showBrokenTag` означают, что в облаке есть:

- заряд батареи;
- температура;
- версия прошивки;
- **дата поверки**;
- признак «прибор сломан».

Также события `GET_HISTORY` (история) и `GET_DECRYPTED_PACKAGES`
(расшифрованные пакеты). У нашей роли история заблокирована; история может быть
доступна другому аккаунту/роли — проверять по согласию владельца.

## 3. Что можно получить по UART (при вскрытии/подключении)

Через площадки `G / RX / TX / G` (3.3 В, FT232BL):

- boot-лог и версия прошивки;
- внутренние счётчики/импульсы;
- температура/сырой заряд;
- self-test/ошибки;
- возможно сервисное меню/команды;
- реакция на вращение крыльчатки.

Это **не публичный интерфейс** и требует физического доступа; в публикацию идут
только методика и правила безопасности, без дампа прошивки.

## 4. Что можно получить по nRF24 (не BLE)

Прибор общается с базой Элехант по проприетарному 2,4 ГГц каналу (nRF24).
Теоретически можно принять пакеты nRF24L01+ приёмником и разобрать, но:

- это сложнее BLE;
- юридически/этически — только свой прибор;
- практической необходимости нет, пока BLE-реклама даёт всё нужное.

## 5. Что прибор НЕ отдаёт

- управление/команды по BLE;
- прошивку/настройки по воздуху (OTA не обнаружен);
- GATT-сервис;
- гарантированный заряд в процентах (только сырой байт);
- дату поверки в BLE (только облако/B1 — гипотеза).

## 6. Что имеет смысл добавить в публичный проект

1. `battery_raw` + попытка калибровки по облаку/сервисному меню.
2. `flags` с пометкой «не выяснено» и накоплением истории.
3. `B1` raw-пакеты (без серийников) для будущего разбора.
4. `packet_interval` и `packets_lost` по счётчику пакетов.
5. Явное разделение `cold`/`hot`/`channel` в HA.
6. Ночной проток как отдельная метрика (литры/час 01:00–05:00).
