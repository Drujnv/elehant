# Элехант: открытое чтение счётчиков воды и газа

> **Черновик для обсуждения.** Ничего не опубликовано. Нужно вместе решить,
> что оставить, что убрать и что вынести в отдельный репозиторий.

Элехант (Elehant) — российские счётчики воды/газа с BLE-рекламой. Приложение
«Счётчики Элехант» нужно только чтобы увидеть показания и отправить их в
ресурсоснабжающую организацию. Здесь — как читать приборы **напрямую**, без
аккаунта и облака, и что ещё они отдают.

Это самостоятельный проект: вода и газ — это деньги, протечки, температура и
контроль ресурсов. Данные должны быть проверяемыми, а не «приложением с красивым
экраном».

## Что уже проверено

- пакет — **реклама BLE**, manufacturer ID `0xFFFF`; GATT и сопряжения нет;
- адрес: `B0:<канал>:02:<номер>`; у СВТ-15 два канала `03` и `04`;
- показания: `u32` в **0.1 литра**, `м³ = raw / 10000`;
- температура воды: `u16` в **0.01 °C**, есть и у **холодных** приборов;
- сверка с приложением — **до последнего знака** (см. `docs/PROTOCOL.md`);
- два канала СВТ-15 — это **два регистра**: ниже/выше +40 °C, а не «дубль»;
- заряд батареи — гипотеза: байт 13, шкала 0–127; облако знает `showBattery`;
- `B0` — данные, `B1` — служебные пакеты (вероятно, серийник/поверка).

## Что прибор отдаёт (кратко)

| Поле | Где | Статус |
|---|---|---|
| объём, 0.1 л | байты 9–12 | подтверждено |
| температура воды, 0.01 °C | байты 14–15 | подтверждено, есть у холодных |
| тип/модель | байты 2–5 | подтверждено |
| номер прибора | байты 6–8 | подтверждено |
| счётчик пакетов | байт 1 | подтверждено |
| заряд батареи, сырой | байт 13 | гипотеза |
| статус/флаги | байт 16 | не выяснено |
| версия прошивки? | байт 16 / B1 | гипотеза |
| служебные B1-пакеты | `B1:*` | сохраняем целиком |

Подробно: `docs/PROTOCOL.md`, `docs/WHAT-IT-OUTPUTS.md`.

## Метрология и ГОСТы

Элехант — **средство измерения утверждённого типа**: СВТ — ГРСИ **72647-18**,
СВД/СВУ — **61754-15**. Температура — измерительный канал **0…+100 °C, ±1,0 °C**;
объём делится по порогу **+40 °C** на два регистра. Ссылки на ГОСТ Р 50193.1-92,
ГОСТ Р 50601-93, ГОСТ 12.2.003-91, 102-ФЗ, ОЦСМ 040196-2018 МП — в
`docs/METROLOGY.md`.

## Интеграции и API

Производитель заявляет **API для интеграции с 1С**; кроме него есть второй способ
забрать данные из **личного кабинета** — конкретный метод/формат не публикуем,
это вопрос к производителю. Наш проект читает BLE напрямую и не зависит от
облака; облако/API — только для сверки и официальных выгрузок.

## Интеграции с умным домом

- **Windows/Linux/macOS** — пассивный BLE-сканер → JSON/CSV → MQTT;
- **ESP32** — BLE-proxy → MQTT → Home Assistant (особенно если счётчик далеко);
- **Home Assistant** — MQTT-сущности воды/газа, температуры, батареи;
- **PostgreSQL/Grafana** — расход по часам/суткам, ночной проток, температура;
- **R4S/ESP32-шлюз** — как дополнительный BLE-приёмник, если адаптер один;
- **Облако Элехант** — только как независимая сверка; персональные данные и API-ключ
  **не публикуем**.

Подробно: `docs/INTEGRATIONS.md`.

## Чем мы отличаемся от других проектов

См. `docs/RESEARCH.md`. Коротко:

1. **Два канала 03/04 объяснены** как два регистра СВТ-15 (ниже/выше +40 °C) —
   в открытых разборах они названы одинаково «СВТ-15» без объяснения.
2. **Температура холодной воды** — приложение её не показывает, а прибор отдаёт;
   мы это измерили и используем.
3. **Сверка с приложением по каждому прибору** — 246.8836 / 1.9967 / 0.5170 /
   1.2417 м³; расхождение только за счёт округления табло.
4. **Аудит байтов** по накопленной истории: видно, какие поля меняются, а какие
   постоянны; сохраняем **каждый пакет целиком**, включая `B1`.
5. **Чиповая часть**: nRF24LE1, UART, SPI-программирование, что можно и нельзя
   снять по воздуху.
6. **Интеграции**: не только «прочитать», но и MQTT/HA/PG/Grafana/ESP32-proxy.
